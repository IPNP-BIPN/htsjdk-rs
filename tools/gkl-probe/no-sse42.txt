# GKL's zlib with SSE4.2 forced off.
#
# NOT an oracle column, and it must not be treated as one. Every other golden in this repository
# comes from running the real library in the pinned container; this one cannot, because no host
# available here lacks SSE4.2. It was produced instead from Intel's own source, jtkukunas/zlib
# (zlib 1.2.13, the version and the patches `libgkl_compression.so` carries), built for
# linux/amd64 with one line changed:
#
#     x86.c:  x86_cpu_has_sse42 = regs[C] & bit_SSE4_2;   ->   x86_cpu_has_sse42 = 0;
#
# That source was first checked against the real library with the flag left alone: at levels 3 to
# 9 it reproduces the recorded GKL column exactly, 28 rows of 28. So the build is the right one,
# and this file is what it emits on the other branch of its own CPU check.
#
# WHY IT IS WORTH HAVING. GKL's output depends on the CPU. With SSE4.2 the fork hashes with a
# CRC-32C of the bytes at the position; without it, with zlib's multiplicative rolling hash. The
# chains fill differently and the match finder answers differently:
#
#     level 3    1 of 4 fixtures unchanged
#     level 4    0 of 4
#     level 5    0 of 4      <- htsjdk's BGZF default
#     level 6    3 of 4
#     levels 7-9 4 of 4      <- the search is thorough enough that chain order stops mattering
#
# So a BAM written by GATK at the default level is not one byte sequence: it is one per CPU class.
# The portability job could not see this, because both hosts it has ever run on report SSE4.2.
#
